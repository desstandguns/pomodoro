# 自動テスト

このフォルダには、ポモドーロタイマーが正しく動くかを **自動で確かめるテスト** が入っています。
アプリを直したあとにテストを動かせば、「前は動いていたのに壊れた」ことにすぐ気づけます。

テストは本物のブラウザ（Chromium）をこっそり動かし、スマホくらいの画面（390×844）でアプリを開いて、
ボタンを押したり、時計を早送りしたりして結果を確認します。
25分待たなくても、時計を「早送り」するので数秒で終わります。

## 何を確かめているか

`app.test.js`（いまある機能）

- 最初は「25:00」「作業」「スタート」になっている
- スタート → 一時停止 → 再開 → リセット が正しく動く
- 25分・45分・60分を選べて、再読み込みしても覚えている。動いている間は選べない
- 作業が終わると休憩（25分→5分、45分→10分、60分→15分）になり、終わると作業に戻る。「今日の完了」が増える
- ほかのアプリに切り替えて2時間たってから戻っても、正しい場所まで進んでいる
- 日付が変わると「今日の完了」が0回から数え直しになる
- 作業が終わると上がる3つの音、休憩が終わると下がる3つの音が鳴る
- 開いたときにエラーが出ない
- ネットがなくても開ける（サービスワーカーがファイルを保存している）

`upcoming.test.js`（これから追加する機能）

- 4回目の作業のあとの「長い休憩」、`#cycle` の「1/4〜4/4」表示
- 「音を試す」ボタン
- 通知ボタン（通知の予約と取り消し）
- 記録（日ごとの回数）
- 画面がスクロールしないこと

まだ作られていない機能のテストは、自動で **スキップ（とばす）** されます。
機能ができあがると、自動でテストされるようになります。

## 動かし方

1. [Node.js](https://nodejs.org/)（バージョン 22 以上）を入れる
2. Playwright（ブラウザを動かす道具）を入れる。リポジトリの外のフォルダに入れると、アプリのフォルダが散らかりません。

   ```sh
   npm install --prefix ~/pw playwright@1.63.0
   ~/pw/node_modules/.bin/playwright install chromium
   ```

3. リポジトリのいちばん上のフォルダで、次を実行する

   ```sh
   NODE_PATH=~/pw/node_modules node --test tests/
   ```

   （Playwright をふつうに入れてある環境なら `node --test tests/` だけで動きます）

最後に `# fail 0` と出れば、すべて合格です。`not ok` と出たテストがあれば、そこが壊れています。

## GitHub での自動実行

`.github/workflows/test.yml` があるので、GitHub に push したときやプルリクエストを作ったときに、
同じテストが自動で動きます。結果はリポジトリの「Actions」タブで見られます。

## ファイルの説明

- `index.js` … `node --test tests/` で最初に読まれ、`*.test.js` をまとめて実行する
- `helpers.js` … 小さなファイルサーバーやブラウザの準備など、共通の道具
- `app.test.js` … いまある機能のテスト
- `upcoming.test.js` … これから追加する機能のテスト
